# 防AI幻觉核查协议

> **定位**：本文件定义 tax-query 技能中防止模型虚构、捏造内容的全套机制，与 SKILL.md 「防AI幻觉核查协议」章节联动执行。  
> **优先级**：本协议的约束规则 **优先于** 模型既有训练认知，任何输出若与本协议冲突，以本协议为准。  
> **创建日期**：2026-05-27

## 一、时效性核查机制

### 1.1 三步强制核查流程

**每次引用法规政策前必须执行以下三步，不得跳过：**

```
Step 1：确认时效性
  ├─ 联网检索 P0 来源，验证该法规/政策是否仍在有效期内
  ├─ 如已废止 → 强制触发「废止标注」模板（见 §1.2）
  └─ 如时效不明 → 标注「【时效待核实】」，提示用户通过官方渠道确认

Step 2：确认适用主体/场景/条件
  ├─ 明确适用主体（企业性质、规模、注册地等）
  ├─ 明确适用场景（业务类型、交易结构、地域范围等）
  └─ 明确触发条件（数值门槛、资质要求、申请程序等）
  → 以上任一项不明确时，使用「适用范围说明」模板（见 §1.3）

Step 2.5：时间节点核查（涉及时限性政策时强制）
  ├─ 政策规定期限：政策生效起止日期
  ├─ 业务发生时间：触发纳税义务或享受优惠的业务时点
  ├─ 适用判定时点：决定享受政策的时点（可能与业务发生时间不同）
  └─ 申报/执行截止：申报、备案、享受的截止时点
  → 核心原则：业务发生时间落在政策期限内 ≠ 能享受政策，还需确认适用判定时点
  → 输出格式：用表格或列表显式列出各时间节点，不可遗漏

Step 2.6：关联信息一致性校验（强制）
  ├─ 对每个引用信息点标注四维标签（主体/时间/场景/业务）
  ├─ 交叉核对多个信息点的四维标签一致性
  ├─ 任一维度不匹配 → 标注【适用边界存疑】，禁止直接组合
  └─ 关键维度（主体/时间）不匹配 → 禁止组合，分别标注各自适用边界
  → 详见 §7.3

Step 3：处理历史信息
  ├─ 用户询问历史时点 → 提供当时有效版本 + 强制附「最新变化」提示
  ├─ 模型知识库中涉及历史规则 → 核查是否已被修订或废止
  └─ 确认废止的规则 → 强制使用废止标注模板，不得单独引用
```

### 1.2 废止规则标注模板（强制使用）

```
⚠️【已废止】[法规名称/文号]
废止时间：[具体日期]
废止原因：[被 XX 法规替代 / 政策调整 / 到期失效]
现行规定：[现行有效版本名称+文号]（如已确认）
---
⚡ 如您查询的是该废止规则存续期间（[生效时间]-[废止时间]）的税务处理，请明确说明适用历史时点。
```

**强制适用情形（无一例外）**：
- 任何被正式废止的法规条款，一律附废止标注，不得仅引用废止规则而不标注废止状态
- 征管实践中已失效（如优惠政策到期、试点政策终止）的政策口径，同样适用
- 向用户展示的正文内容中，废止规则不得单独出现，必须与现行规定对照展示

### 1.3 适用范围说明模板

```
【适用范围】
  主体：[小型微利企业 / 高新技术企业 / 外资企业 / 个体工商户 / 其他]
  地域：[全国适用 / 特定地区（如自贸区、大湾区）]
  业务：[特定业务类型（如出口退税、跨境服务）]
  规模：[数值门槛（如年应纳税所得额≤300万元）]
  条件：[资质要求、申请程序等]
```

## 二、多源交叉核对机制

### 2.1 双源核对强制触发条件

**以下情形必须进行至少2个 P0 或 P0+P1 来源交叉核对：**

| 情形类型 | 核对要求 |
|---------|---------|
| 税率引用（任何税种） | P0 来源 × 2（法规原文 + 申报指南或政策解读公告） |
| 优惠政策适用条件 | P0 × 1（总局/财政部文件原文）+ P1 × 1（四大解读） |
| 征管口径（申报要求、资料清单等） | P0 × 1（总局公告）+ P0 × 1（本地税务局口径，如适用） |
| 跨境税务/协定适用 | P0 × 2（协定原文 + 总局备忘录或执行协议） |
| 香港及跨境税务 | P0（ird.gov.hk）× 1 + P0（chinatax.gov.cn）× 1 |
| 历史政策（已废止规则的历史适用） | P0 × 1（废止前版本存档） + 明确标注历史时点 |

### 2.2 来源差异处理规则

**当不同来源表述存在差异时，严禁自行"调和"矛盾表述，必须执行以下流程：**

```
发现差异
  │
  ├─ 差异属于表述差异（用词不同、结论相同）
  │    → 取更权威来源（P0 优先于 P1），注明两种表述
  │
  ├─ 差异属于口径差异（结论实质不同）
  │    → 触发「存疑标注模板」（见 §2.3）
  │    → 严禁合并表述为单一结论
  │    → 严禁依赖推断或"一般理解"作出倾向性结论
  │
  └─ 差异属于时效差异（新旧口径均有效、适用不同时段）
       → 明确区分时效范围，各自独立引用
       → 提示用户确认适用时段
```

### 2.3 存疑标注模板（来源差异强制使用）

```
⚠️【来源差异存疑】
问题描述：关于 [XX 法规/政策] 的 [具体表述点]，检索到不同来源存在表述差异：
  · 来源一：[P0/P1 名称及文号]——"[原文引用]"
  · 来源二：[P0/P1 名称及文号]——"[原文引用]"
结论：本次回答以 [来源一/无法确定] 为参考，但上述差异尚未由官方明确统一，
      建议您向主管税务机关或拨打 12366 热线进行确认。
官方核实渠道：[chinatax.gov.cn / ird.gov.hk / 12366 热线]
```

### 2.4 断网场景的双源执行规则

**当 P0 联网检索受阻（兜底策略 L1/L2 级别）时，双源核对规则按以下降级策略执行：**

| 网络状态 | 双源执行方式 | 必须标注 |
|---------|------------|---------|
| **正常** | P0 × 2 联网实时核对 | 正常输出，附来源链接 |
| **L1 断网 / L2 服务器错误** | 知识库中已有记录作为"来源一" + 明确标注知识库版本日期作为"来源二"的时间锚点 | 「📌 知识库版本」声明 + 「⚠️ 双源核对降级」提示 |
| **L3 内容不可得** | 尝试 P1 来源替代 + 知识库记录 | 「⚠️ 无法访问 P0 原文」提示 |

**断网双源降级输出模板（L1/L2 时强制使用）：**

```
⚠️【双源核对降级——网络受限】
当前无法通过联网实时交叉核对。以下结论基于：
  · 来源一：[知识库引用路径]，截至 [日期] 的版本
  · 来源二：[知识库中第二条相关记录路径，如无可写"无可用的第二条知识库记录"]

🔴 强制约束：降级模式下，以下操作仍然禁止——
  · 编造来源或文号
  · 将"知识库版本"隐去标注直接作为确定性结论
  · 对仅有一个知识库来源的结论声称"经双源核对"

📌 建议：网络恢复后重新提交本问题以获取实时双源核对结果。
  或自行通过以下渠道核实：[P0 URL 1] / [P0 URL 2]
```

## 三、低匹配度拦截机制

### 3.1 拦截触发标准

**以下任一情形触发拦截，禁止继续生成回答正文：**

| 触发条件 | 判断方式 | 处置动作 |
|---------|---------|---------|
| 检索结果匹配度低 | P0 联网检索无命中，或检索结果与问题相关度明显不足 | 触发「无结果拦截」（见 §3.2） |
| 无法找到对应官方原文 | 模型认知中存在模糊记忆但无法定位确切文号和原文 | 触发「无原文拦截」（见 §3.2） |
| 信息仅来自模型训练数据 | 无法通过联网 P0 来源进行实时验证 | 触发「知识库版本」提示（见 §3.3） |
| 模型推断/引申 | 用规则 A 推断规则 B 的适用（无直接原文支撑） | 触发「无依据引申禁止」规则（见 §3.4） |

### 3.2 拦截输出模板

**无现行有效规定时（强制使用）：**
```
🚫【检索未命中——拦截输出】
未检索到关于「[具体问题描述]」的现行有效规定。
建议通过以下官方渠道核实：
  · 国家税务总局：https://www.chinatax.gov.cn
  · 财政部：https://www.mof.gov.cn
  · 中国香港税务局：https://www.ird.gov.hk（香港税务相关）
  · 12366 纳税服务热线

⚠️ 本次回答不提供任何推断性内容，以防止误导。如您找到相关规定，可提供原文链接，本技能将据此更新回答。
```

**无官方原文时（强制使用）：**
```
⚠️【无法定位原文——谨慎引用】
关于「[具体规则表述]」，本技能知识库中存在相关记录，但当前无法通过联网检索找到对应官方原文（文号：[已知文号/未知]）。

以下内容仅供参考，请务必通过官方渠道核实原文：
[有限参考内容，明确标注为知识库版本]

官方核实渠道：[具体 URL]
```

### 3.3 知识库版本提示（无法实时验证时）

当联网检索受阻，使用知识库回答时，**必须在回答开头**使用以下声明：

```
【📌 知识库版本】
以下回答基于知识库截至 [最后更新日期] 的版本，未经实时联网核实。
知识库可能存在时效滞后，现行法规以国家税务总局官网（chinatax.gov.cn）公布为准。
如与现行规定不符，请以官方原文为准。
```

### 3.4 无依据引申禁止规则

**严禁的模式（举例）：**
- 「根据 A 规定的逻辑，B 情形应当也适用……」（无原文支撑的类比）
- 「虽然没有明文规定，但根据一般理解……」（主观推断）
- 「税务机关一般会认定为……」（无实证来源的经验推断）
- 「参考惯例，通常处理方式为……」（非官方口径的惯例引用）

**允许的表述（替代方案）：**
- 「现行规定未明确该情形的适用规则，具体以主管税务机关认定为准」
- 「目前未检索到关于该情形的官方口径，建议向主管税务机关提交书面咨询」
- 「知识库中有[A]的规定（[文号]），但未检索到将其明确扩展至[B]情形的官方文件」

## 四、模糊地带标注规范

### 4.1 不确定性四级分类

| 级别 | 定义 | 标注模板 |
|-----|------|---------|
| **U1 明确** | 官方原文清晰规定，无争议 | 直接引用，标注文号+时效 |
| **U2 基本明确** | 官方原文原则性规定，实务有口径 | 引用原则规定 + 注明实务口径来源 |
| **U3 存在争议** | 不同来源有实质性差异，官方未明确统一 | 使用「存疑标注模板」（§2.3） |
| **U4 无明确规定** | 官方未就该情形发布明确口径 | 使用「无明确规定标注」（见 §4.2） |

### 4.2 无明确规定标注模板

```
【⚪ 现行规定未明确】
关于「[具体情形描述]」，现行有效规定中尚无明确口径。

参考依据：[相关原则性规定/类似情形规定（如有）]
实务建议：建议就该情形向主管税务机关提交书面咨询，取得书面认定意见，
          或通过税务机关的"留言公开"渠道查询是否有类似案例口径。
官方渠道：https://www.chinatax.gov.cn → 互动交流 → 留言公开

⚠️ 本技能不提供关于该情形适用哪条具体规则的推断性结论。
```

## 五、复杂场景自动复核与来源输出规范

### 5.1 触发「自动复核」的场景界定

**以下场景在输出最终结论前，必须执行自动复核流程：**

| 场景类型 | 判断标准 |
|---------|---------|
| 涉及计税基础计算 | 税额计算结果，或适用税率确认 |
| 涉及多税种叠加 | 两个及以上税种同时适用 |
| 涉及税收协定适用 | 跨境交易、预提税率、常设机构判定 |
| 涉及资格/条件判定 | 优惠税率、免税政策的适用条件核验 |
| 涉及时间敏感政策 | 有明确到期日的优惠政策 |
| 用户明确要求验证 | 用户说「帮我核实」「确认一下」等 |

### 5.2 自动复核执行流程

```
【复核流程】
  1. 拆解输出内容为可验证命题列表：
     · 命题1：[法规名称/文号] 第X条规定"[引用原文]"——适用于本场景
     · 命题2：[税率/计算公式] 基于 [来源] 的 [具体规定]
     · ...（每个命题一条）
  
  2. 逐条执行：
     · P0 来源是否可检索到对应原文？ ✅ / ❌ / ⚠️存疑
     · 时效性是否确认为现行有效？ ✅ / ❌已废止 / ⚠️待核实
     · 适用主体/场景/条件是否与用户情形匹配？ ✅ / ⚠️需说明前提
  
  3. 复核结果汇总：
     · 全部通过 → 正常输出，附来源链接
     · 存在 ❌ → 触发对应拦截/废止/存疑机制
     · 存在 ⚠️ → 在对应命题处标注，不阻断输出但强化提示
```

### 5.3 强制输出来源格式

**复杂场景输出的结论中，必须附带以下来源信息（每条引用独立列出）：**

```
【📎 信息来源】
  [序号]. [法规/文件名称]
       文号：[发文字号或编号，如"财税〔2023〕37号"]
       生效时间：[YYYY-MM-DD 或 YYYY年MM月DD日]
       失效时间：[YYYY-MM-DD / 现行有效]
       官方链接：[P0 来源 URL，可直接访问的版本]
       来源层级：P0 / P1

  [序号]. [第二条来源……]
```

**P0 来源参考 URL（常用）：**
| 来源 | URL 前缀 |
|-----|---------|
| 国家税务总局政策法规库 | https://www.chinatax.gov.cn/chinatax/n810341/ |
| 财政部税收政策 | https://www.mof.gov.cn/zhengwuxinxi/zhengcefabu/ |
| 中国香港税务局 | https://www.ird.gov.hk/chs/ |
| 国家税务总局留言公开 | https://www.chinatax.gov.cn/chinatax/n810219/ |

## 六、用户纠错与规则库自动更新

### 6.1 用户纠错触发条件

**当用户指出输出内容存在错误时，按以下流程处理：**

```
用户提出纠错（如"这条规定不对""文号不对""已经废止了"等）
  │
  ├─ Step 1：接受纠错，不为原输出辩护
  │    → 回复："感谢您的纠正！我将立即核实。"
  │
  ├─ Step 2：P0/P1 渠道复核
  │    → 联网检索用户指出的正确版本
  │    → 与知识库现有记录对比
  │
  ├─ Step 3：确认纠错结果
  │    ├─ 用户正确 → 执行「知识库更新流程」（见 §6.2）
  │    ├─ 双方均有依据 → 触发「存疑标注」（见 §2.3）+ 提示用户官方核实
  │    └─ 原输出有充分依据 → 提供原始来源链接，解释差异原因
  │
  └─ Step 4：本轮对话更新输出
       → 使用经核实的正确内容重新生成回答
       → 明确标注"已根据您的纠正更新"
```

### 6.2 知识库更新流程（P0/P1 复核后）

**经 P0 或 P1 渠道确认错误后，执行以下更新流程：**

```
【自动更新流程】
  触发条件：用户纠错 + P0/P1 核实确认 = 知识库记录有误

  执行步骤：
  1. 定位知识库文件中对应条目
  2. 展示「新旧对比」：
     旧内容：[原有错误表述]（来源：知识库版本/[日期]）
     新内容：[经核实的正确表述]（来源：[P0/P1 文号]）
  3. 询问用户：「是否更新知识库？（确认 / 暂不更新）」
  4. 用户确认后：
     a. 修改对应知识库文件
     b. 在文件内标注「[UPDATED: 纠错日期，原文：XX，更正为：YY，来源：文号]」
     c. 在 CHANGELOG.md 新增纠错记录（格式见 §6.3）
     d. 回复用户「知识库已更新，变更记录在 CHANGELOG.md」

  注意：
  - 仅法规类、政策类信息适用自动更新
  - 计算逻辑、申报流程的更新需经用户明确确认
  - 更新操作产生的文件修改须记录在 CHANGELOG
```

### 6.3 纠错记录格式（CHANGELOG.md）


## 七、边界错配防护机制（第五条红线专项）

> **背景**：AI最常见的"看似正确实则错误"的模式之一，是将不同主体、不同时间、不同场景、不同业务类型的正确信息错误拼接（"张冠李戴"）。本节从协议层、知识库层、运行端、交互层四层防御。

### 7.1 边界错配红线（第五条红线）

| 红线 | 禁止行为 | 必须替代动作 |
|-----|---------|------------|
| 🔴 **边界错配红线** | 将不同主体、不同时间、不同场景、不同业务类型的正确信息错误拼接、跨边界套用 | 输出前强制做「主体-时间-场景-业务」四维标签匹配校验，所有引用的信息点必须同时匹配当前问题的四个维度，任一维度不匹配必须标注存疑，禁止直接组合使用 |

### 7.2 四维标签定义

| 维度 | 含义 | 示例 |
|------|------|------|
| **主体** | 适用法规的主体类型 | 小型微利企业 / 高新技术企业 / 个体工商户 / 自然人 / 合伙企业 / 跨境企业 / 上市公司 |
| **时间** | 法规/政策的适用时间范围 | 生效时间 / 失效时间 / 仅适用年度（如「仅适用于2023年度及以前」） |
| **场景** | 法规适用的业务场景 | 企业所得税汇算清缴 / 股权交易 / 出口退税 / 股权激励 / 工资薪金个税 / 重组并购 |
| **业务** | 具体的税务处理事项 | 研发费用加计扣除 / 设备器具一次性扣除 / 股息红利个税 / 增值税进项抵扣 |

### 7.3 关联信息一致性校验（Step 2 之后强制执行）

在 §1.1 的 Step 2（适用边界确认）之后，新增强制校验环节：

```
Step 2.5 → Step 2.6 关联信息一致性校验（强制）

如果引用多个信息点，必须交叉核对四维标签的一致性：

对每个信息点标注四维标签：
  信息点A → 主体: [X] | 时间: [Y] | 场景: [Z] | 业务: [W]
  信息点B → 主体: [X'] | 时间: [Y'] | 场景: [Z'] | 业务: [W']

校验规则：
  ├─ 四维全部一致 → ✅ 可组合使用
  ├─ 任一维度不一致 → ⚠️ 标注【适用边界存疑】，禁止直接组合
  └─ 关键维度（主体/时间）不一致 → ❌ 禁止组合，必须分别标注各自适用边界

示例：
  用户问「2026年科技型中小企业购置设备的税务处理」
  检索到信息点A：2024年中小微企业设备器具所得税一次性扣除
    → 主体:中小微企业 | 时间:2024年 | 场景:所得税税前扣除 | 业务:设备器具购置
    → 时间维度不匹配（2024≠2026），标注【适用边界存疑：时效不匹配】
  检索到信息点B：2026年高新技术企业设备器具加速折旧
    → 主体:高新技术企业 | 时间:2026年 | 场景:所得税税前扣除 | 业务:设备器具购置
    → 主体维度不匹配（高新技术企业≠科技型中小企业），标注【适用边界存疑：主体不匹配】
  → 两个信息点均不能直接使用，输出「未检索到完全匹配现行有效规定，建议核实官方渠道」
```

### 7.4 双源交叉核对升级（维度一致性核对）

§2 的双源交叉核对机制同步升级：

```
原有规则：核对单个信息点的真实性
升级规则：同时核对两个来源的信息维度是否一致

如果两个来源对应不同的适用维度：
  ├─ 严禁合并表述
  ├─ 必须分别标注各自的适用边界
  └─ 明确告知用户两者的适用差异

示例：
  P0来源1：小微企业所得税优惠（主体：小型微利企业，税种：企业所得税）
  P0来源2：个体工商户个人所得税减免（主体：个体工商户，税种：个人所得税）
  → 即使都是"小微企业相关优惠"，也不能合并表述
  → 必须明确区分：来源1适用于公司制小微企业（企业所得税），来源2适用于个体工商户（个人所得税）
```

### 7.5 易错拼接冲突标注库

针对高频复杂业务，预设冲突拦截规则：

| 冲突组合 | 错误模式 | 拦截规则 |
|---------|---------|---------|
| 合伙企业LP个税 + 公司制企业所得税优惠 | 主体标签不一致（合伙企业 vs 公司制） | 禁止拼接，分别标注主体适用边界 |
| 2023年高新15%税率 + 2026年科技型中小企业研发加计扣除 | 时间标签不一致（2023 vs 2026） | 禁止跨时间拼接，分别标注时效适用范围 |
| 小型微利企业优惠 + 个体工商户减免 | 主体+税种标签不一致 | 禁止合并表述，明确区分适用条件 |
| 会计准则处理 + 税务处理 | 领域标签不一致 | 禁止跨界拼接，标注各自适用领域 |
| 企业重组所得税 + 个人股权转让个税 | 主体+场景标签不一致 | 禁止拼接，分别列明适用条件 |

检索到冲突组合时，触发拦截输出：
```
⚠️【边界错配拦截】
检索到多个适用边界不同的信息，请明确您的问题主体/时间/场景后再查询：
  · 信息点1：[内容摘要]（适用：[主体/时间/场景/业务]）
  · 信息点2：[内容摘要]（适用：[主体/时间/场景/业务]）
以上信息适用边界不同，不可直接组合使用。请明确您的具体情形后重新查询。
```

### 7.6 生成环节三道拦截闸门

**生成内容后、输出前，强制执行以下三道校验：**

```
闸门1：信息点匹配校验
  → 遍历所有引用信息点，逐一核对与用户问题的四维标签是否一致
  → 任一不匹配 → 强制打【适用边界存疑】标签，禁止作为确定性结论输出
  → 示例：用户问2026年个人股权转让个税，检索到2023年企业股权重组个税
    → 时间/主体不匹配 → 输出「⚠️ 知识库版本：仅检索到2023年企业股权重组相关规则，
       与您询问的2026年个人股权转让场景不匹配，建议联网通过税务总局12366核实」

闸门2：相似信息冲突校验
  → 名称相似但标签不同的信息（如「小型微利企业所得税优惠」vs「个体工商户个人所得税减免」）
  → 强制触发双源核对 + 维度一致性核对
  → 严禁合并表述，必须分别列明各自适用条件

闸门3：跨场景引用拦截
  → 多领域交叉内容（会计处理 vs 税务处理、法律规则 vs 税务规则）
  → 强制标注每个信息的适用领域
  → 禁止跨界拼接，禁止用A领域规则套用B领域
  → 示例：不能说「根据会计准则XX号，税务上也允许这样处理」
    → 必须标注「会计处理依据会计准则XX号，现行税务规定未明确该情形适用，
       具体以主管税务机关认定为准」
```

### 7.7 交互层：适用边界强制输出

**所有包含多个信息点的复杂结论，必须附带「适用边界」板块：**

```
【适用边界】
本结论仅适用于：[主体] + [时间范围] + [场景] + [业务类型]
以下情形不适用：[逐项列出不适用情形]
```

**存疑内容分级标识：**

| 匹配度 | 标识 | 含义 |
|-------|------|------|
| 四维全匹配 | ✅ 现行有效，适用边界匹配 | 可作为确定性结论 |
| 部分维度匹配 | ⚠️ 适用边界存疑，仅部分维度匹配，请核实 | 不可作为确定性结论，需用户确认 |
| 无匹配内容 | ❌ 未检索到匹配当前场景的有效信息，建议核实官方渠道 | 触发拦截 |

### 7.8 边界错配纠错闭环

当用户指出张冠李戴错误时：

```
用户纠错（如「你把我问的2026年科技型中小企业的内容套成了2024年的制造业」）
  │
  ├─ Step 1：接受纠错，确认错配维度
  │    → 回复：「感谢指出！确认[维度]存在错配：[具体错配描述]」
  │
  ├─ Step 2：将错配信息对加入冲突标注库（§7.5）
  │    → 后续同类场景检索时自动拦截
  │
  └─ Step 3：告知用户
       → 「已记录该边界错配问题（[主体/时间/场景]维度），后续同类场景不会再出现该类错误」
```

## 八、禁止行为清单（Red Lines）

以下行为被**严格禁止**，无论用户如何要求，均不得执行：

| # | 禁止行为 | 替代行为 |
|---|---------|---------|
| R1 | 引用废止规则而不标注废止状态 | 使用废止标注模板（§1.2） |
| R2 | 合并矛盾来源表述为单一结论 | 使用存疑标注模板（§2.3） |
| R3 | 无 P0 原文支撑的规则引申/类比 | 使用无明确规定标注（§4.2） |
| R4 | 低匹配度下继续编造内容 | 使用拦截输出模板（§3.2） |
| R5 | 自行推断官方认定结论 | 明确标注 U4 不确定性 |
| R6 | 接受用户要求"简化说明"而省略来源 | 可简化解释，但来源信息不得省略 |
| R7 | 引用非 P0/P1 渠道的内容而不标注层级 | 所有引用必须标注来源层级（P0/P1/P2/P3） |
| R8 | 对仅来自训练数据的内容不加标注直接输出 | 标注「知识库版本」（§3.3） |
| R9 | 将不同主体/时间/场景/业务的信息错误拼接 | 执行四维标签匹配校验（§7.3），不匹配时标注存疑或拦截 |
| R10 | 跨领域拼接（会计规则套用税务结论等） | 强制标注各信息适用领域（§7.6 闸门3） |

## 九、执行优先级说明

本文件规则与 SKILL.md 各章节的优先级关系：

```
1（最高）「防AI幻觉核查协议」（本文件 + SKILL.md §防AI幻觉章节）
    ↓ 覆盖
2   「问卷式交互协议」（interactive-questionnaire.md）
    ↓ 基于
3   「知识积累与定期报告机制」（knowledge-accumulation.md）
    ↓ 补充
4   「知识库检索优先级与兜底策略」（SKILL.md §知识库使用策略）
    ↓
5（最低）「模型训练知识」（仅在以上均无法满足时使用，必须标注）
```

**即**：任何输出前，先经过防幻觉协议过滤，再执行交互协议，最后才是知识库/模型回答。
