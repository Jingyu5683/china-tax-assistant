# 估算模板调用规则

> 本文档定义估算模板之间的调用逻辑、数据流向和组合编排规则。
> 当用户面对综合性筹划问题时，需要调用多个模板并串联输出，形成支持决策的完整方案。

---

## 一、模板体系架构

```
                    用户需求
                       │
                       ▼
              ┌─────────────────┐
              │  场景识别 & 路由  │  识别用户需求涉及哪些模板
              └────────┬────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
     ┌─────────┐ ┌─────────┐ ┌─────────┐
     │ CT-001  │ │ CT-002  │ │ CT-003  │   专项层
     │固定资产  │ │研发加计  │ │亏损弥补  │   各模板独立计算
     │一次性扣除│ │扣除+高新 │ │         │
     └────┬────┘ └────┬────┘ └────┬────┘
          │            │            │
          └────────────┼────────────┘
                       ▼
              ┌─────────────────┐
              │    CT-004       │   汇总层
              │ 单体利润&税费   │   汇总各专项输出 → 完整利润表+税负分析
              └────────┬────────┘
                       │
                       ▼
              ┌─────────────────┐
              │  多主体对比      │   决策层
              │  方案A vs 方案B  │   横向对比 → 输出决策建议
              └─────────────────┘
```

### 层级定义

| 层级 | 模板 | 职责 |
|------|------|------|
| **专项层** | CT-001/002/003 | 单一税种/单一事项的详细计算，输出精确的税会差异、节税额、指标上下限 |
| **汇总层** | CT-004 | 将各专项输出汇入利润表，完成全链路税费计算 |
| **决策层** | 非固定模板 | 对比多主体/多方案的CT-004输出，做横向对比和决策判断 |

## 二、模板调用触发规则

### 2-1. 单模板触发

| 用户需求关键词 | 推荐模板 |
|--------------|---------|
| 一次性扣除、500万、加速折旧、设备购置税前扣除 | CT-001 |
| 加计扣除、研发费用、研发预算节税 | CT-002 Part A |
| 高新指标、高新门槛、科技人员占比、软件企业指标 | CT-002 Part B |
| 亏损弥补、税亏弥补、亏损到期、亏损税盾 | CT-003 |
| 利润表、税负测算、综合税负、年度预算 | CT-004 |
| 股权转让、股东退出、并购重组、跨境转让 | CT-008 |
| 59号文特殊处理、股权收购 | CT-008 |
| 非货币性资产投资、技术出资、递延纳税 | CT-009 |
| 116号文、41号文 | CT-009 |
| 不动产转让、土增税、增值税选择 | CT-010 |

### 2-2. 组合调用触发

| 用户需求特征 | 调用组合 | 说明 |
|------------|---------|------|
| 提到研发+设备投入 | CT-001 + CT-002 → CT-004 | 设备一次性扣除影响税会差异，研发费用影响加计扣除，均汇入利润表 |
| 提到亏损+研发 | CT-002 + CT-003 → CT-004 | 加计扣除减少应纳税所得额→可用于弥补亏损的利润减少，存在此消彼长 |
| 提到高新+设备+研发 | CT-001 + CT-002 → CT-004 | 设备投入计入高新指标，研发费用同时满足加计扣除和高新口径 |
| 提到投资项目、新设主体、集团投资 | 全套 + 多主体对比 | 见下方典型案例 |

## 三、调用顺序与数据流向

### 3-1. 执行顺序原则

```
Step 1: 识别需要哪些专项模板（专项层）
Step 2: 专项模板并行计算，互不依赖
Step 3: 各专项输出汇入 CT-004（汇总层）
Step 4: 如需多主体对比，每个主体各做一遍 Step 2-3
Step 5: 横向对比各主体 CT-004 输出（决策层）
```

### 3-2. 数据流向明细

```
CT-001 输出                    → CT-004 输入
─────────────────────────────────────────────
税会差异（纳税调减/调增）        → 3-2-2 / 3-2-1
一次性扣除节税额               → 税负分析参考
递延所得税负债                 → 资产负债表参考（不在CT-004利润表内）

CT-002 输出                    → CT-004 输入
─────────────────────────────────────────────
加计扣除额                     → 3-2-2 纳税调减
节税额                         → 税负分析参考
高新/软件指标达标情况           → 决策层参考（影响税率选择）

CT-003 输出                    → CT-004 输入
─────────────────────────────────────────────
当期弥补亏损额                 → 3-2 弥补以前年度亏损
亏损到期风险                   → 决策层参考

CT-008 输出                    → CT-004 输入
─────────────────────────────────────────────
股权转让所得                   → 投资收益/营业外收入
印花税                         → 税金及附加
特殊性税务处理递延             → 纳税调减（递延确认）

CT-009 输出                    → CT-004 输入
─────────────────────────────────────────────
每年确认转让所得（116号文）    → 纳税调增明细
增值税视同销售税额             → 增值税进销项
取得股权计税基础调整           → 资产负债表参考

CT-010 输出                    → CT-004 输入
─────────────────────────────────────────────
增值税                         → 增值税明细
土地增值税                     → 税金及附加
契税                           → 决策层（买方成本）
企税/个税                      → 所得税
```

### 3-3. 交叉影响（需特别注意）

| 交叉点 | 影响 | 处理方式 |
|--------|------|---------|
| 研发加计扣除 vs 亏损弥补 | 加计扣除减少应纳税所得额→可用于弥补亏损的所得减少 | 先做CT-002算出加计扣除额，再在CT-003中以调减后所得计算弥补 |
| 设备一次性扣除 vs 亏损弥补 | 第1年大额调减可能使应纳税所得额为负→新增亏损 | 先做CT-001算出税会差异，再在CT-003中判断是否产生新亏损 |
| 高新15%税率 vs 亏损弥补 | 高新期间弥补亏损按15%算税盾，非高新期间按25%算 | CT-003的税盾测算需考虑高新资质是否持续 |
| 高新指标 vs 加计扣除口径 | 两套口径不完全一致 | CT-002 Part B单独做指标倒推，不直接用Part A的数据 |
| 小微优惠 vs 一次性扣除 | 一次性扣除可能使所得降至300万以下→触发小微优惠 | 在CT-004中判断是否满足小微条件，调整适用税率 |
| 股权转让 vs 非货币性资产投资 | 股权置换可能同时涉及两种处理 | 现金/资产支付部分走CT-008，股权支付部分需判断59号文vs116号文 |
| 不动产出资 vs 不动产出售 | 不动产出资可享116号文递延，出售则当期纳税 | 在CT-009/CT-010间根据交易目的选择 |
| 股权转让 vs 不动产间接转让 | 通过转让持有不动产的公司股权间接转让不动产 | CT-008+CT-010联动：关注土增税穿透风险 |

## 四、典型案例：集团新投资项目决策

### 场景描述

> 某集团公司拟投资一个新项目，涉及研发、设备投入、内部关联交易。需评估：
> - 方案A：用现有主体（已认定为高新技术企业，15%税率）开展项目
> - 方案B：新设独立主体开展项目

### 4-1. 调用流程

```
                    用户需求
                       │
          "现有主体 vs 新设主体" 投资决策
                       │
                       ▼
            ┌──── 识别需要哪些模板 ────┐
            │                          │
    涉及设备投入 → CT-001          涉及研发 → CT-002
    涉及亏损弥补 → CT-003          需要利润表 → CT-004
            │                          │
            └──────────┬───────────────┘
                       │
                       ▼
              按主体分别执行
            ┌────────┴────────┐
            ▼                 ▼
       方案A（现有主体）    方案B（新设主体）
       ┌──────────────┐   ┌──────────────┐
       │CT-001: 设备   │   │CT-001: 设备   │
       │  一次性扣除   │   │  一次性扣除   │
       │              │   │              │
       │CT-002: 研发   │   │CT-002: 研发   │
       │  加计扣除     │   │  加计扣除     │
       │  高新指标倒推  │   │  高新指标倒推  │
       │  (已认定，    │   │  (新设，需    │
       │   维持指标)   │   │   从0起步)    │
       │              │   │              │
       │CT-003: 亏损   │   │CT-003: 亏损   │
       │  (可能已有    │   │  (初期大概率  │
       │   历史亏损)   │   │   亏损)       │
       │              │   │              │
       │CT-004: 汇总   │   │CT-004: 汇总   │
       └──────┬───────┘   └──────┬───────┘
              │                  │
              └────────┬─────────┘
                       ▼
                 多主体对比表
              ┌─────────────────┐
              │ 方案A vs 方案B  │
              │ · 税负对比      │
              │ · 现金流对比    │
              │ · 高新资质风险  │
              │ · 关联交易影响  │
              │ · 综合决策建议  │
              └─────────────────┘
```

### 4-2. 方案A（现有主体）专项测算要点

| 模板 | 特殊关注点 |
|------|-----------|
| CT-001 | 现有主体已高新，一次性扣除的税盾按15%计算（vs 新主体25%），税盾价值更低 |
| CT-002 Part A | 研发费用可加计扣除，但需注意与现有研发项目的费用归集区分 |
| CT-002 Part B | **维持**高新指标：新增研发投入是否足以维持研发费用占比≥3-5%？新增人员是否影响科技人员占比？项目收入是否计入高新收入？ |
| CT-003 | 现有主体可能有历史亏损可用弥补，加计扣除+一次性扣除后应纳税所得额减少→亏损吸收可能放缓 |
| CT-004 | 税率15%（高新），但需关注：①新增业务是否属于高新领域 ②指标是否仍达标 ③关联交易定价对收入成本的影响 |

### 4-3. 方案B（新设主体）专项测算要点

| 模板 | 特殊关注点 |
|------|-----------|
| CT-001 | 新主体适用25%税率（未认定高新），一次性扣除税盾按25%计算，税盾价值更高 |
| CT-002 Part A | 研发费用可加计扣除，但新设初期研发占比可能偏高（收入少） |
| CT-002 Part B | **申请**高新资质：需要3年数据才能申请认定，期间按25%缴税。倒推：第1-3年需累积多少研发投入才能在第4年达标？ |
| CT-003 | 新设主体初期大概率亏损，亏损按5年弥补（未认定高新，不适用10年）。需测算：何时开始盈利？亏损能否在到期前弥补完？ |
| CT-004 | 税率25%（前3年），可能第4年起享15%（若高新认定成功）。需逐年用不同税率测算。关联交易定价影响利润 |

### 4-4. 关联交易专项分析

> 关联交易不在任何一个模板内单独覆盖，但在方案对比中至关重要。

| 分析维度 | 方案A（现有主体） | 方案B（新设主体） |
|---------|-----------------|-----------------|
| 设备采购 | 向集团内关联方采购，需关注转让定价 | 同左 |
| 技术服务 | 向集团内关联方支付技术服务费，需合理定价 | 同左，但初期可能大量向关联方采购服务 |
| 资金借贷 | 集团内借款，需关注资本弱化（2:1债资比）和利率合理性 | 同左，但新设主体可能注册资本小、借款比例高，资本弱化风险更大 |
| 利润转移 | 现有主体合并报表，内部交易抵消 | 新设主体独立报表，关联交易定价直接影响单体利润→影响高新指标和亏损弥补 |

**转让定价关注点**：
- 设备采购：是否按独立交易原则定价？有无可比非关联价格？
- 技术服务费：收费标准是否合理？是否虚增费用转移利润？
- 资金借贷：利率是否在金融企业同期同类贷款利率范围内？
- 特许权使用费：如涉及集团内知识产权授权，需关注是否合理

### 4-5. 决策对比输出框架

| 对比维度 | 方案A（现有主体） | 方案B（新设主体） | 差异 | 影响判断 |
|---------|-----------------|-----------------|------|---------|
| **5年累计净利润** | | | | |
| **5年累计经营净现金流** | | | | |
| **5年累计所得税** | | | | |
| **综合税负率** | | | | |
| **高新资质风险** | 维持指标/需追加投入 | 3年后方可申请/不确定 | | |
| **亏损弥补风险** | 历史亏损可吸收 | 初期亏损5年期限/能否弥补完 | | |
| **关联交易风险** | 合并报表内 | 独立报表，定价敏感 | | |
| **管理成本** | 低（无新增主体） | 高（新设+维护+审计） | | |
| **灵活性** | 低（业务混在一起） | 高（独立运营/未来可出售） | | |

**决策建议输出要素**：
1. 量化对比（5年累计税后净现金流差异）
2. 定性风险（高新/亏损/关联交易三维度）
3. 敏感性分析（关键假设变动对结论的影响）
4. 建议方向 + 合规声明

## 五、模板扩展规则

### 5-1. 新增模板的编号规则

| 编号 | 预留场景 | 状态 |
|------|---------|------|
| CT-001 | 固定资产一次性税前扣除 | ✅ 已建 |
| CT-002 | 研发费用加计扣除+高新/软件指标 | ✅ 已建 |
| CT-003 | 所得税亏损弥补 | ✅ 已建 |
| CT-004 | 单体利润及各项税费 | ✅ 已建 |
| CT-008 | 股权转让税负测算 | ✅ 已建 |
| CT-009 | 非货币性资产投资递延纳税测算 | ✅ 已建 |
| CT-010 | 不动产交易多税种协调测算 | ✅ 已建 |
| CT-005 | 转让定价/关联交易分析 | 🔲 待建 |
| CT-006 | 增值税留抵退税测算 | 🔲 待建 |
| CT-007 | 非居民企业预提税 | 🔲 待建 |

### 5-2. 新增模板的接入要求

1. 必须包含"关键参数确认清单"，所有政策相关参数标注参考文号
2. 必须在"与估算模板体系的衔接"一节中写明与其他模板的数据流向
3. 如为专项层模板，需写明输出如何汇入CT-004
4. 如为决策层模板，需写明依赖哪些专项层/汇总层模板
5. 更新本文件的调用触发规则和数据流向图

### 5-3. 模板版本管理

- 每个模板文件头部标注版本号
- 政策变化时更新模板中的政策文号和"状态"列，版本号+0.1
- 新增计算逻辑或调整结构时，版本号+1.0
- 更新后在本文件索引表中同步版本号
